CURRENT PRODUCT STATE

TTS engines include Android/RHVoice, Edge, Azure, OpenAI, Google Gemini and xAI Grok.

Silero v5.5 and the PyTorch Android runtime were removed from the base app on 2026-09-19. The local Silero path was broken on-device by a TorchScript argument-type mismatch and made the APK very large. The build no longer downloads the Silero model asset and no longer depends on org.pytorch:pytorch_android. Do not re-add a large local runtime/model to the default APK without a separate optional-download or flavor design.

xAI Grok TTS supports playback and MP3 export. Grok-specific pronunciation/delivery logic lives in GrokEditorMarkup.kt and GrokEditorToolbar.kt rather than ReaderActivity.

COMPACT TOP CONTROLS

The old large multi-row bottom control panel was replaced by a compact top control strip above the document. Playback, speed, edit, engine, voice and file/export controls are compact; engine and voice use popup menus. Export progress/status stays compact and long diagnostics are truncated instead of expanding the whole panel.

Edit mode keeps its own compact top strip above the editor, including play, engine, voice, Grok tools and save. This keeps Save reachable while the Android keyboard is open and the user edits the bottom of a long document.

EDITOR SEARCH

Edit mode now has a top-only search workflow for proofreading long generated audio/text:
- a magnifier button is in the compact editor toolbar;
- it opens a compact search row immediately below the top toolbar;
- previous/next search wrap through the full unsaved editor text;
- the found phrase is selected and auto-scrolled into view;
- search is case-insensitive;
- closing search returns focus to the editor;
- no search/menu controls are placed at the bottom where the keyboard can cover them.
Search behavior is isolated in ReaderEditorSearchController.kt with unit tests for forward/backward wrapping.

EDITOR

Edit mode is a proofreading/listening workspace.

- The normal large bottom player is hidden during editing.
- A compact toolbar stays above the text while the Android keyboard is open.
- Toolbar: Listen/Pause, dedicated Grok stress button, `Grok ▾`, Save.
- Grok stress uses Unicode combining acute U+0301. Existing stress in the same word is replaced; other words are untouched.
- `Grok ▾` groups delivery/speed/pitch and pauses/breath/sounds into submenus.
- Save text/audio controls remain on the normal reading screen, not in edit mode.
- ReaderActivity uses adjustResize so the IME should resize the editor instead of covering controls.

PLAYBACK FROM EDITOR / CURSOR

Playback must start from the exact requested text position, not merely from the beginning of the containing sentence.

- With only a caret: start at the caret.
- With a selection: start at the beginning of the selection; selection-only playback is not a product requirement.
- For xAI Grok, if the position is inside an open wrapping tag such as `<slow>`, GrokEditorMarkup.playbackStartOffset() may move the effective start back to the opening tag so the style instruction remains valid.
- ReaderActivity keeps a playbackStartOffsetOverride for the first segment only. Later segments use their full text.
- The same exact-first-segment rule applies to Android TTS and cloud TTS.
- Unsaved editor text is used immediately for auditioning.

PLAYBACK WAITING INDICATOR

PlaybackBusyIndicator.kt animates the play control while a TTS request/engine is preparing. It rotates small triangle glyphs rather than the entire button. When audio actually starts, the editor control becomes Pause. Export already has a real percent progress bar; network TTS generation does not invent fake percentages when the provider gives no byte-level progress.

FAST NAVIGATION FOR LONG TEXTS

ReaderFastScroller.kt is a draggable overlay on the right side of the Reader scroll area.

- The old Android scrollbar was only an indicator and is disabled.
- The custom thumb can be grabbed and dragged directly to jump through a long book.
- Tapping the track also jumps to that region.
- It is hidden for short documents.
- Text/editor right padding leaves room for the thumb.

DOCUMENT IMPORT

The single "Open PDF / Word / TXT" picker now handles the main reading-document formats:
- PDF uses pdfbox-android and extracts the embedded text layer page by page with disk-backed scratch storage;
- legacy Word .doc/.dot uses Apache POI HWPF, with Word 6/95 fallback;
- modern Word .docx/.docm/.dotx/.dotm is parsed from word/document.xml with XmlPullParser;
- TXT-like input supports UTF-8, UTF-16LE/BE and practical Windows-1251/Windows-1250 fallbacks;
- PDF visual line wrapping is normalized into readable paragraphs, including conservative de-hyphenation across line breaks;
- Word paragraph breaks, tabs, explicit breaks and basic table row/cell separation are retained;
- image-only/scanned PDFs without an embedded text layer are reported as such; OCR is not bundled.

Document import logic stays in DocumentTextExtractor.kt and ImportedTextNormalizer.kt rather than MainActivity.

LARGE-DOCUMENT SAFETY

ReaderLimits.kt centralizes safety ceilings.

- warning threshold: 750,000 characters;
- hard editable/display document limit: 2,000,000 characters;
- general source stream hard limit: 64 MiB; PDF source hard limit: 256 MiB using a temporary file;
- expanded DOCX document.xml hard limit: 32 MiB;
- library hard item ceiling: 5,000;
- library metadata index ceiling: 8 MiB;
- existing library body storage ceiling remains 1 GiB.

DocumentTextExtractor checks source size before/until reading and bounds DOCX XML expansion. MainActivity refuses documents beyond the display limit and warns for very large accepted documents.

LIBRARY STORAGE DECISION

Do not migrate to SQLite yet.

Current LibraryStore already stores each document body in a separate `library/<id>.txt`. `index.json` contains metadata only (id/title/source/date). The library screen is paginated and excerpts are streamed from only the beginning of each text.

LibraryStore now also caps item count/index size and writes index metadata through a temporary file before replacement. SQLite becomes worthwhile later if the product needs thousands of searchable/sortable records, full-text search, tags, or relational metadata.

GROK TAG SAFETY

Wrapping tags include soft, whisper, loud, build/decrease intensity, higher/lower pitch, slow/fast, sing-song, singing and emphasis. Inline events include pauses, breathing and supported vocal sounds.

Grok wrapping tags must remain balanced across playback/export chunks. If playback begins inside a tagged span, effective start moves back to the relevant opening tag.
